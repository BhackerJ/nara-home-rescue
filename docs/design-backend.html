3 · 发件箱：coordinator 发一条消息的固定顺序

第 ②、④ 步都走这五步。在任何一处崩溃，恢复后都不会重复。去掉了 revision 校验和第 6 步"预设拔电源"。

1读 ServiceCase

这一步已经完成，就跳过

2查发件箱

已有这一步的消息（上次没来得及发），跳到第 4 步

3stageStep

算出结果，连同消息原文写进发件箱

4原样发出

idempotencyKey = <caseId>:<kind>，Relay 按 key 返回同一条

5completeStep

记下 relayMessageId，清发件箱，改 status 和 checkpoint

为什么不会重复
  • 消息没发出去 → 重算一次
  • 发出去了没记录 → 原样重发，Relay 按 key 返回原来那条（同 key 不同内容报 409）
  • 已经记录的步骤 → 直接跳过
  • 预约另由 ProviderCalendar 按 <caseId>:book 防重复，key 重复时返回已有预约并记 reused: true
coordinator 重启时
  • reconnect(token) 接回 Relay 身份（token 在 relay/state.json）
  • CaseIndex.list() 找到没结束的工单，逐个 beginRecovery(bootId, pid)
  • messages.list 从最后记录的 relayMessageId 之后补拉，这些消息记 backfilled: true
  • 从 checkpoint 的下一步继续
provider 处理一条消息
  • claim(messageId)：处理过就直接返回
  • slot_request → offer(caseId, requested)：首选永远被占，返回前两个空时段 → 发 reject
  • accept → 每 300ms 查 isApproved(caseId)，店里点了 CONFIRM 才往下 → book(slot, key) → 发 confirm
  • key <caseId>:provider:<kind>，发完 markReplied
  • 启动时先 messages.list，补处理没回复的请求

出错统一处理：actor 调不通、outcome_unknown、Relay 发送失败，一律等 200ms 重读 actor 重进循环；30 秒还不行把工单设成 failed。
